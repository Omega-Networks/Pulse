| | |
|---|---|
| **Status** | Proposed |

## Principle

**The NetBox schema is the contract; Pulse stops re-deriving it by hand.** Types are generated from the instance's own OpenAPI document, sync becomes changelog-driven after one full mirror, interfaces join the persisted digital twin, and writes go out only through schema-typed request bodies behind quality gates. Do it properly from the beginning: every phase ends at a lab-verified gate, not a green build.

---

## 1. Objective

Four staged outcomes on one feature branch (`feat/netbox-openapi-sync` off `main`, one sub-branch per phase):

1. **P1 — Generated client.** Replace the bespoke `APIRequest`/`NetboxResource`/hand-written Codable layer with a client generated by Apple's swift-openapi-generator from a vendored, path-filtered NetBox schema. Read-path behaviour parity, with known correctness bugs fixed deliberately.
2. **P2 — Interfaces in SwiftData.** Interfaces become a persisted `@Model`, pulled in full during full sync (accepted one-time cost), replacing the per-site-open fetch and the in-memory `InterfaceCache`.
3. **P3 — Changelog incremental sync.** After the first full mirror, boot applies deltas from `/api/core/object-changes/` against a persisted watermark; full re-pull only on first sync, forced resync, or retention-gap fallback.
4. **P4 — MACD writes.** Write functionality through generated `*Request` types, starting with interfaces and cables, with the service designed for Moves/Adds/Changes/Deletions across cables, interfaces, devices, and sites.

Out of scope: Zabbix/PowerSense paths (`ZabbixResource`, `PowerSenseZabbixResource`, `PowerSenseMonitorService`, Event sync, spatial clustering) are untouched except where explicitly noted for invalidation sequencing. Zabbix is JSON-RPC and has no OpenAPI document; it stays bespoke.

## 2. Current-state findings (codebase review, 2026-08-12)

Full inventories live in the review transcripts; the load-bearing facts:

### 2.1 The bespoke layer

Fourteen `NetboxResource` conformers over 9 boot-synced object types (roles, types, tenants, regions, site groups, sites, racks, devices, services) plus 3 on-demand types (static devices, device bays, interfaces). All GET in practice. `APIRequest.fetchAllPages` follows `next` recursively with `limit=1000` pages. Auth is `Authorization: Token …` injected per request from `Configuration.shared` (Keychain token, UserDefaults server URL — both mutable at runtime).

### 2.2 Correctness defects the refactor must fix (not port)

1. **`postSite` never POSTs.** Method selection lives in `NetboxResource.request` and only upgrades `DeviceResource` (`NetboxResource.swift:63–65`). `SiteResource` with a body goes out as GET; `AddSiteWindow` "creates" a site, gets the site list back, and reports success. Site creation has never worked.
2. **One bad record aborts a whole sync step.** `Wrapper.results: [T]` decodes strictly; every per-record `throw SwiftDataError.missingData` (guards in all 13 Properties decoders) fails the entire page decode. The "ignore record" comments are wrong. Interacts catastrophically with delete-and-reconcile: a partial fetch must never feed the deletion pass.
3. **New-object insert bug (Tenant, Site).** `modelContext.insert` sits only in the `lastUpdated`-equal branch (`ProviderModelActor.swift:266–270`, `:929–933`); brand-new objects take the mismatch branch and persist only via implicit relationship insertion. A site with no group/tenant/region would silently vanish.
4. **`Site.region` has never synced** — CodingKey `region_netbox` vs NetBox's `region` (`Site.swift:172`). Fixing it will suddenly wire regions; verify UI assumptions.
5. **`getTenantGroups` is called from nowhere**, so tenant→group links never resolve. `TenantGroup.lastUpdated` also never decodes (missing raw value).
6. **Date fragility.** Single format `yyyy-MM-dd'T'HH:mm:ss.SSSSSS'Z'`; DRF omits fractional seconds when microseconds are zero → record fails guard → page aborts (defect 2).
7. **`try!` crash paths** on nested site/role/device_type decodes (`Device.swift:477–510`, `StaticDevice.swift:206–219`, `Rack.swift:193–194`).
8. **Write encoders don't match NetBox writable serializers**: status as `{"value":…}` instead of string; `device_type` as `{"model":…}`; `primary_ip` as a top-level string; duplicate-key encodes in `InterfaceProperties.encode` (deviceId and deviceName both under `.device`); `{"rack": {"id": null}}` for rackless devices; read-only fields encoded; `custom_fields` always fully overwritten; copy-paste `self.deviceTypeId = deviceRoleId` (`Device.swift:600`).
9. **Silent type mismatches**: `Interface.mtu`/`speed` decoded as String but NetBox sends integers → always `""` (permanent data loss); `CableProperties` decode shape wrong (moot — never called).
10. **Sentinel flattening**: API nulls become `0` / `""` / `"Unknown"` and downstream logic branches on them (`zabbixId != 0`, `groupId != 0`, `primaryIP == "Unknown"`).
11. **Swallowed failures + false freshness**: device/service batch task groups discard child errors, then stamp `lastNetBoxUpdate = Date()` (client clock) anyway. Every save error is `print`ed and reported as success. `try? fetch` yielding an empty map turns "fetch failed" into "insert everything as new".
12. **Sync races**: boot (`PulseApp.verifyContainer`) and manual (`SyncDashboardView.syncData`) construct independent `ProviderModelActor`s with no mutual exclusion; duplicate-id defensive code exists because this bites.
13. **Hardcoded instance-specific filters are load-bearing**: `manufacturer_id__n=5`, `role_id__n=29/30`, static-device `role_id=6/7/18/27`, camera roles 11/35 in `Device.swift`. They define both fetch scope and local deletion scope; they must move to configuration, and the delete pass scope must match.

### 2.3 Interface flow today

Fetched lazily per site open (`SiteView`/`DetailSheet` `.task` → `SiteDataService.loadAllSiteData` → one HTTP request **per device**), landing in the memory-only `InterfaceCache` actor (no persistence, no eviction, no `clearCache`). Gone on relaunch; offline mode has no topology edges. `getInterface(withId:)` is an O(total-interfaces) scan used per edge; `setInterfaces` posts one notification per device (notification storm → repeated edge recompute). Consumers: `SiteGraphView.computeEdges`, `LayoutManager.createGraph` (duplicated edge derivation), `InterfacesTable`, `DeviceFaceplate`/`InterfacePopover`, `MemberCell`. Edges derive from `connected_endpoints` (first entry only), not Cable objects; cables are never fetched.

### 2.4 Sync state today

No watermark of any kind. `SyncProvider.lastNetBoxUpdate` is client-clock, written by only 2 of 9 stages, and advanced even on partial failure — unusable for changelog purposes. Full 9-stage pull runs on every launch. Upsert semantics are delete-and-reconcile per type (deletions in NetBox do propagate, but only via full pulls, and scoped by the hardcoded query filters). `InitializationState.totalSteps` hardcodes the full-pull progress UI.

### 2.5 Project facts

Xcode project, hand-edited pbxproj (house rule), 3 targets, app target Swift 6.0 (tests 5.0), macOS/iOS 26.0, no build plugins or script phases today. SPM deps pinned/reviewed (SwiftTerm exact-pinned). Tests are XCTest with in-memory `ModelContainer`s and hermetic JSON fixtures; `ServicePropertiesDecodingTests` is the house template and the only NetBox decoder coverage. ADRs in `docs/architecture/` (`NNNN-kebab-title.md`, Principle/Context/Non-negotiables/What-ships-when/Structural-enforcement/Verification/Alternatives/Revision-history). Branch convention `feat/<kebab>`, one PR per slice, conventional-commit titles, "a green build is not a passing gate".

## 3. External facts (verified 2026-08-12, sources at end)

- **NetBox 4.6.x current.** Schema served at `GET /api/schema/` (drf-spectacular, server-side cached 24h keyed to release version), emits **OpenAPI 3.0.3**. `COMPONENT_SPLIT_REQUEST: True` → separate `Foo` / `FooRequest` / `PatchedFooRequest` component schemas; read-only fields only in responses. Since 4.2.5 related fields on write accept **integer PK or object** (oneOf in schema). Choice fields: read `{value,label}`, write plain string. `custom_fields` is a free-form object in the schema — per-field typing stays hand-rolled. **4.6 collapsed all operation tags to a single `api` tag → filter the schema by paths/operation IDs, never tags.**
- **swift-openapi-generator 1.13.0** (runtime + `swift-openapi-urlsession` 1.3.1 transport). Supports OAS 3.0/3.1. Config `openapi-generator-config.yaml` supports `filter:` by `operations` / `paths` / `schemas` (union + transitive closure of component dependencies); the CLI has a `filter` subcommand to emit the filtered document for review. Known pain on huge specs (30–60s incremental builds); maintainer-endorsed mitigations: filter aggressively, generate ahead of time with the CLI, isolate generated code.
- **Date footgun (confirmed both directions):** runtime default `.iso8601` rejects fractional seconds; `.iso8601WithFractionalSeconds` rejects timestamps *without* them; DRF emits microseconds only when non-zero. A custom lenient `DateTranscoder` (try fractional, fall back to non-fractional) is mandatory.
- **Changelog:** `/api/core/object-changes/` (moved from `extras` in 4.1). Fields: `id, time, user, user_name, request_id, action{value,label}, changed_object_type ("dcim.device"), changed_object_id, object_repr, prechange_data, postchange_data`. Filters: `time_after`/`time_before`, `changed_object_type`, `changed_object_id`, `action`, `request_id`; standard `?ordering=time`; offset pagination (+ 4.6 keyset `start`). **Deletions appear** (`action=delete`, `postchange_data` null). Default `CHANGELOG_RETENTION` **90 days**. Caveats: changes made without request context (migrations, shell) produce no records; `CHANGELOG_SKIP_EMPTY_CHANGES` means changelog and `last_updated` can disagree; snapshots carry related objects as **bare IDs** → re-fetch by id for authoritative state. `last_updated__gte` polling is not an alternative: it cannot see deletions.
- **Write semantics:** PATCH for partial updates. Cable create: `a_terminations`/`b_terminations` = arrays of `{"object_type": "dcim.interface", "object_id": N}`. **4.6 adds optimistic locking**: `ETag` on single-object GETs, `If-Match` on PUT/PATCH → 412 on conflict. Tokens: per-token `write_enabled` flag; v1 `Token` header deprecated in 4.6 (removed in 5.0), v2 `Bearer nbt_…` current — middleware must support both. Bulk ops are all-or-none.
- **Schema churn is real** across 4.x minors (4.0 Brief* rename, 4.1 changelog move, 4.2.5 write-shape change, 4.6 tag collapse + ETag). Vendor the spec per NetBox version, regenerate and diff on every minor upgrade, gate features on `/api/status/` version at connect time.

## 4. Target architecture

```
┌────────────────────────────────────────────────────────────────┐
│ Vendored spec (docs/netbox/openapi-filtered.yaml, from OUR     │
│ instance's /api/schema/, filtered by paths via generator CLI)  │
└───────────────┬────────────────────────────────────────────────┘
                │ swift-openapi-generator CLI (AOT, committed)
┌───────────────▼───────────────┐
│ Pulse/NetBox/Generated/       │  Types.swift, Client.swift — never hand-edited
├───────────────────────────────┤
│ NetBoxClientFactory           │  URLSessionTransport
│  • AuthMiddleware (Token/     │  lenient DateTranscoder
│    Bearer, read per request   │  server URL read per request from
│    from Configuration.shared) │  Configuration (runtime-mutable)
├───────────────────────────────┤
│ NetBoxSyncEngine (actor)      │  single owner; boot + manual + delta
│  • FullSyncPass (mirror)      │  paginated fetch-all helper
│  • DeltaSyncPass (changelog)  │  watermark on SyncProvider
│  • per-type upsert/delete     │  delete pass gated on full-fetch success
│  • NetBoxFilterConfiguration  │  replaces hardcoded __n IDs, shared by
│                               │  fetch scope, delete scope, delta filter
├───────────────────────────────┤
│ Mapping layer (Generated →    │  thin, tested, owns custom_fields typing
│  SwiftData models / VOs)      │  and sentinel policy
├───────────────────────────────┤
│ NetBoxWriteService (P4)       │  MACD ops on generated *Request types,
│                               │  ETag/If-Match, validation-body surfacing
└───────────────────────────────┘
```

Decisions and rationale:

- **AOT CLI generation, committed generated code, vendored filtered spec** — not the build plugin. Reproducible builds, reviewable schema diffs in PRs, no build-tool plugin in a hand-maintained pbxproj, no per-build generation cost. Regeneration is a documented script (`Scripts/regenerate-netbox-client.sh`) run on NetBox upgrades. This is the sovereignty position too: the generated code is plain Swift we own outright and could freeze.
- **Path filtering** to only the operations Pulse uses (~15 list/detail path pairs + object-changes + status). Keeps `Types.swift` compilable and reviewable.
- **One sync owner.** `NetBoxSyncEngine` is a single app-level actor; `verifyContainer`, SyncDashboard, and the delta scheduler all call into it; overlapping requests coalesce. Watermark writes happen only after a delta batch fully applies.
- **Sentinel policy**: P1 mapping layer preserves today's sentinels (behaviour parity, flagged as debt); the new P2 `Interface` model uses honest optionals from day one; broader normalization is a later, separate change.
- **Custom fields** (`coordinate_x`, `coordinate_y`, `zabbix_id`, `zabbix_instance`) get one typed accessor in the mapping layer over `OpenAPIObjectContainer`; writes send only the fields being changed.
- **Error surfacing**: generated `ClientError`/undocumented-status responses map into `RequestStatusManager` (kept) and `Logger` (subsystem `netbox`); NetBox 4xx validation bodies reach the operator, not just the console.

## 5. Phase plan and quality gates

Branching: `feat/netbox-openapi-sync` off `main`; sub-branches `feat/netbox-openapi-sync-p1-client`, `…-p2-interfaces`, `…-p3-changelog`, `…-p4-writes`, each merging into the feature branch by PR after its gate passes. ADR 0003 ships with P1 and gains amendment sections per phase (house style).

### P0 (folded into P1 start) — Spikes, in order, before any migration code

1. Pull `/api/schema/` from the lab instance; record NetBox version from `/api/status/`; filter with the generator CLI; commit spec + config + generated output; measure build impact.
2. Prove the lenient `DateTranscoder` against real instance payloads (both fractional and zero-microsecond timestamps).
3. Prove auth middleware (Token and Bearer forms) and runtime server-URL/token change (edit in Settings mid-session must take effect without relaunch).
4. Decode a full real `dcim_devices_list` page into generated types — confirm nullability, choice enums, custom_fields access.

### P1 — Generated client, read-path parity + deliberate fixes

Scope: replace all 9 boot pulls plus static devices/device bays/interfaces (still cache-backed in P1) with generated operations behind the mapping layer; new pagination helper (iterative, not recursive); unified upsert (single code path, correct inserts — fixes defect 3); per-element-tolerant decoding with **delete pass gated on complete fetch**; `NetBoxFilterConfiguration` replaces hardcoded IDs; add `getTenantGroups` to the sync order; fix `region_netbox`; single `NetBoxSyncEngine` owner (fixes the race); honest error propagation (no watermark/freshness stamp on partial failure); delete `APIRequest.swift`, `NetboxResource.swift`, and all hand-written Properties decode/encode paths.

**Gate 1 (lab, against real NetBox):** object counts per type match NetBox exactly after full sync (including tenant groups and region links for the first time); deliberately corrupt one record in a fixture → that record is skipped, page survives, delete pass does not run for that type; kill the network mid-sync → no deletions, no freshness stamp, error surfaced in UI; decoder + upsert test suite green (fixture-based, per type, in the `ServicePropertiesDecodingTests` mould); build time acceptable.

### P2 — Interfaces into SwiftData

Scope: `Interface` `@Model` (`@Attribute(.unique) id`, `#Index` on `deviceId` and denormalized `siteId`, scalar reference ids — `connectedEndpointId`, `lagId`, `bridgeId`, `parentId` as **optionals, nil not 0** — plus denormalized `connectedEndpointDeviceId`; relationship to `Device` with cascade delete); full interface sync stage after devices (paginated stream-processing, page-by-page upsert, never materializing the full list; batch-size logic extended; per-batch id-scoped prefetch, not full-table); interface stale-delete pass with the same full-fetch gating; delete `InterfaceCache` and `.interfacesDidUpdate`; consumers move to `@Query`/`FetchDescriptor` (fixes the `InterfacesTable`/`DeviceFaceplate` first-open race); edge derivation becomes one indexed per-site fetch + local join, shared by `SiteGraphView` and `LayoutManager`, returning Sendable `InterfaceVO`-based edges (models never cross actor boundaries); `mtu`/`speed` become integers (fixes defect 9); container schema addition + `totalSteps` update; the cold first interface sync runs as a background phase with progressive availability, not inside the launch-blocking loading screen.

**Gate 2 (lab, 12K+ devices):** site open works fully offline after one sync (topology edges render from store); relaunch requires zero interface HTTP; edge parity against P1 rendering on reference sites (duplicate-edge dedupe is an accepted, flagged visual change); interface sync throughput measured and memory-flat page-by-page; instruments profile shows site-open queries index-backed; full test pass including topology eligibility and edge-derivation unit tests.

### P3 — Changelog incremental sync

Scope: watermark (`lastObjectChangeId` + `lastObjectChangeTime`, NetBox server time only) on `SyncProvider`; boot becomes: watermark present → delta pass, else full mirror; delta pass pages `/api/core/object-changes/?time_after=…&ordering=time`, groups by object, applies in FK order (role/type/tenant-group/tenant/region/site-group → site → rack → device → interface → service), **re-fetches each changed object by id** for authoritative state (snapshots carry bare IDs), per-id delete primitives per type, client-side filter-boundary handling (a device edited into the excluded set = local delete; out of it = insert) via the same `NetBoxFilterConfiguration`; cable changes re-fetch both terminated interfaces; retention/gap fallback (oldest retained change newer than watermark, watermark id missing, or counts=0 with watermark set → forced full mirror); watermark advances only after a fully-applied batch; "Delete All Data"/"Delete Sync Provider" reset the watermark; severity recompute for sites affected by device deltas; delta application sequenced against the Zabbix problem timer; SyncDashboard shows watermark age and last delta result; manual "Full Resync" button retained.

**Gate 3 (lab scenario matrix):** for each object type: create/update/delete in NetBox → next delta pass converges Pulse exactly (verified by count + spot fields); device moved across the role/manufacturer filter boundary in both directions; cable connect/disconnect updates both interfaces and topology; watermark not advanced when a batch fails mid-apply (kill network mid-delta, re-run, converges); retention-gap simulation forces full resync; cold boot with fresh watermark performs no full pull and completes in seconds; interleaved Zabbix polling during delta application causes no stranded events.

### P4 — MACD writes

Scope: `NetBoxWriteService` over generated `*Request`/`Patched*Request` types — designed for MACDs across cables, interfaces, devices, and sites; **enabled first for interfaces and cables** (interface enable/disable, description, PATCH; cable create/delete with `a/b_terminations` GenericObject shape), with device and site operations implemented behind the same interface but gated for later enablement; optimistic locking via ETag/If-Match where the instance supports it (4.6+; feature-gate on `/api/status/`), last-write-wins fallback documented; every successful write feeds the object back through the delta-apply path (no local speculative state divergence); NetBox validation bodies surfaced to the operator verbatim; `custom_fields` writes send only changed fields; fix/rebuild `postSite` and `AddSiteWindow` on the new path (site create is a *new* capability — it never worked); write token posture documented (dedicated service account, `write_enabled`, model/action-scoped permissions); dormant broken write scaffolding (`postDevice`, `updateDevice`, `CableProperties` encoder, `InterfaceStatusCell` local toggle) deleted or rewired.

**Gate 4 (lab, write round-trips):** interface toggle/description round-trips and is re-read authoritatively; cable create between two lab interfaces renders as a topology edge after the next delta pass, delete removes it; 412 conflict path exercised (edit in NetBox UI between read and write) surfaces a human-readable conflict, no silent overwrite; validation-error path (e.g. duplicate cable) surfaces NetBox's message; a PATCH never clobbers unrelated custom_fields (verified by diffing NetBox changelog records for the write); write-disabled token → clean read-only degradation.

## 6. Risk register

| Risk | Mitigation |
|---|---|
| Partial fetch + delete-and-reconcile = mass local deletion | Delete pass strictly gated on complete, successful fetch of that type (P1 structural rule, tested) |
| Fixing decoders changes behaviour (regions appear, tenant groups populate, unnamed devices survive) | Each named in ADR; Gate 1 parity run reviews diffs deliberately, not accidentally |
| Generated types churn on NetBox upgrades | Vendored spec per version; regenerate+diff on minors; `/api/status/` version gate; compiler surfaces breaks |
| Build-time blowup from big schema | Path filtering; AOT generation; measure at Gate 1; escalate to separate module only if measured |
| Changelog misses out-of-band changes (migrations, scripts without request context) | Periodic safety full mirror (configurable, e.g. weekly or manual); documented operator caveat |
| Watermark corruption / clock semantics | Server-time+id watermark only from changelog records; advance only post-apply; reset paths wired to destructive UI actions |
| SwiftData scale (tens of millions of interface rows at 1M devices) | Denormalized `siteId` + indexes; page-by-page ingest; id-scoped batch prefetch; Gate 2 profiling at 12K with projections; 1M-scale lab pass before national deployment |
| Writes racing sync | All writes go through `NetBoxSyncEngine`'s owner actor; post-write authoritative re-fetch |
| Swift 6 strict concurrency vs generated code + SwiftData models | Models never cross actor boundaries (VO pattern); generated client is Sendable; spike in P0 |

## 8. P0 lab amendments (2026-08-13)

Lab findings from the P0 spikes (NetBox 4.6.2, generator 1.13.0; full notes `docs/netbox/p0-spike-notes.md` on `feat/netbox-openapi-sync-p1-client`) supersede this plan where they conflict. The plan text above is retained unedited; these amendments govern:

1. **Generator filtering is exact-match only** — no globbing on `paths:`. The config enumerates exact operation IDs (29 GET operations). The plan's "~15 path pairs" phrasing stands conceptually; the mechanism is operation IDs.
2. **Tags are NOT collapsed on 4.6.2** — 14 real tags observed, contradicting §3's "4.6 collapsed all tags" claim (research overreach from issue #21937). Operation-ID filtering remains the contract regardless, as it is resilient to either tagging scheme.
3. **ETag is absent from the schema document** but present on the wire as a **weak validator** (`etag: W/"<last_updated>"`). Amendment to P4: RFC 7232 specifies strong comparison for `If-Match`, under which a weak validator never matches — NetBox's actual comparison behaviour is implementation-defined and MUST be proven in the lab (both the 412 path and the success path) before optimistic locking is relied on; otherwise fall back to documented last-write-wins. Header handling lives in middleware since the schema doesn't declare it.
4. **`MAX_PAGE_SIZE` is 1000; default page size is 50.** The page iterator must request `limit=1000` explicitly and follow `next`; never rely on the server default.
5. **Zero-microsecond timestamps did not occur in the lab snapshot**; the lenient transcoder handles both shapes and is unit-tested, but Gate 1 fixtures must include a synthetic zero-microsecond timestamp (and an offset-form `+00:00` timestamp) so the guarantee is pinned by test, not by absence of counterexample.
6. **Generated client lives in a local SPM package `NetBoxAPI`** — required, not optional: the generated code takes an unqualified `Configuration` that collides with Pulse's `Configuration` singleton. This supersedes the plan's "in-target first, escalate if measured" position; the module boundary also delivers the build-isolation benefit (~10 s incremental after touching the factory).
7. **This generate is GET-only.** Write operations were omitted because this schema's `PatchedWritable*Request` components generate non-`Encodable` Swift (empty `oneOf` case). New P4 entry spike: identify the offending schema construct (candidates: drf-spectacular Null/Blank enum variants on nullable choice fields; the int-or-object related-field `oneOf` from PR #18451), patch it deterministically in the vendoring pipeline (the same scripted patch step that already fixes security schemes), and only then regenerate with write verbs; fallback is hand-written `Encodable` request bodies for the small write surface, pinned by tests against the schema. P4 does not start until this spike has an answer.

Additional standing rule from P0: the vendoring pipeline's schema patches (security schemes today, write-body fixes later) must be scripted and deterministic — raw fetched schema in, generate-ready document out, diffable in PRs. **The vendored document must also have its `servers:`/instance URL normalized before commit — this is a public repository; lab endpoints do not belong in the tree.**

## 9. P1 as-built amendments (2026-08-13, tip 96a662a)

The pre-push audit found this plan's tracked copy had lost §8 (overwritten at branch checkout) and that §4's diagram no longer matches the ship. As-built deviations, governing over §4:

1. **Layout:** generated code lives in the local SPM package `NetBoxAPI/Sources/NetBoxAPI/` (per §8.6), not `Pulse/NetBox/Generated/`. The integration layer is `Pulse/NetBox/` (11 files).
2. **The generated client is a type library in P1.** Runtime list traffic goes through `NetBoxLiveFetcher` (URLSession, typed `URLQueryItem` queries, offset pagination via `NetBoxPageIterator`); generated `Components.Schemas` types are used for decoding only. **Resolved in ADR 0003:** `NetBoxLiveFetcher` is the ratified P1 transport; `NetBoxClientFactory`/`NetBoxAuthMiddleware` are retained as the future generated-transport path; both share the single `NetBoxAuthorization` rule (fail-closed empty token, https+host). Do not grow a second Token/Bearer implementation.
3. **Pagination is offset-based and never dereferences `next`** — this structurally removes the cross-origin token-leak class; the residual risk is unbounded accumulation (page cap required, see fix batch).
4. `Package.resolved` is committed at the workspace path; NetBoxAPI has no separate resolved file (single-workspace resolution). Platforms in `NetBoxAPI/Package.swift` are below the app minimums — align or annotate.
5. Info.plist carries a pre-existing `NSAllowsLocalNetworking` ATS relaxation, so plain `http://` to a local NetBox would succeed silently — the https-only validator is therefore a required code-level control, not defense-in-depth.

## 10. P2 as-built amendments (2026-08-13)

1. **Unresolved device / missing site is out of scope, not `skipped`.** Counting those rows as skipped would permanently disable the interface delete pass on any instance with manufacturer-excluded devices (the interface list has `device_role_id__n` but not `manufacturer_id__n`). Poisoned JSON still increments `skipped` and gates delete.
2. **Streaming delete gate:** batches apply during the walk. A mid-walk throw leaves upserts, does not delete, does not stamp. The delete pass uses the union of accepted ids from every page.
3. **Interface page cap is 60_000** (1M devices × 50 IF / 1000 + 20% slack). Other types stay at 100.
4. **Consumers use `FetchDescriptor` + `InterfaceVO`**, not site-scoped `@Query`. Table edit UI stays ephemeral on VO copies (writes are P4).
5. **`ProviderModelActor` is kept** — `UpdateModal` still calls it for Zabbix event updates.
